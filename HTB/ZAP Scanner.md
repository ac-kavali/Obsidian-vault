# ZAP Scanner — Notes

> [!info] What is ZAP Scanner? ZAP (Zed Attack Proxy) has a built-in web scanner, similar to Burp Scanner. It maps a site with the **Spider**, then finds bugs with the **Passive Scanner** (automatic) and **Active Scanner** (sends attacks).

All steps below use the **main ZAP desktop app** (Sites tab / History tab / top menu) — not the HUD overlay in the browser.

---

## 🧠 Vocabulary (simple definitions)

| Term             | Plain-English meaning                                                                                                                                                              |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Spider**       | ZAP's crawler — follows links/forms to map out a website. Same idea as Burp's Crawler.                                                                                             |
| **Ajax Spider**  | A smarter spider that can also find links loaded dynamically by JavaScript (things a normal spider would miss).                                                                    |
| **Passive Scan** | ZAP reads pages it has _already_ seen and looks for obvious problems. It sends **no attack traffic** — totally safe.                                                               |
| **Active Scan**  | ZAP actively sends attack payloads (SQLi, XSS, command injection, etc.) to every page/parameter it found. This is what actually confirms vulnerabilities — and it's noisy/riskier. |
| **Site Tree**    | The folder-like map of the target website, built by the Spider. Found in the **Sites** tab.                                                                                        |
| **Scope**        | The list of URLs/sites ZAP is allowed to test.                                                                                                                                     |
| **Alert**        | A single finding/issue ZAP reports (e.g. "Missing X-Frame-Options header").                                                                                                        |
| **Risk**         | How dangerous an alert is: **High / Medium / Low / Informational**.                                                                                                                |
| **Confidence**   | How sure ZAP is that the alert is real (not a false positive).                                                                                                                     |
| **HUD**          | An in-browser overlay version of ZAP's controls. This guide skips it and uses the desktop app instead.                                                                             |

---

## 🕷️ 1. Spider (build the site map)

**What it does:** Crawls the site by following every link and form it can find, building a full map of pages.

**How to run it from the ZAP UI:**

1. Make sure the target has been visited at least once (browse it through ZAP's proxy, or it already appears in the **Sites** tab).
2. Go to the **Sites** tab (left panel).
3. Right-click the target URL → **Attack → Spider...**
4. In the popup, confirm the target URL and click **Start Scan**.
5. If the site isn't in your **Scope** yet, ZAP will offer to add it automatically — accept this so the scan is allowed to run.
6. Watch progress in the **Spider** tab that opens (shows % complete and requests sent).
7. When it finishes, check the **Sites** tab — the tree now shows every page/file discovered (e.g. `robots.txt`, `sitemap.xml`, subfolders).

> [!tip] Ajax Spider Regular Spider misses links generated by JavaScript. Right-click the target → **Attack → Ajax Spider...** to catch those too. Run it _after_ the normal Spider — it's slower but more thorough.

---

## 🔍 2. Passive Scanner (automatic, safe)

**What it does:** As the Spider requests pages, ZAP automatically inspects each response in the background — no extra action needed, and no attack traffic sent. Good for quick, low-risk findings like missing security headers or possible DOM-based XSS.

**How to view results:**

1. Open the **Alerts** tab (bottom-left area of the main ZAP window).
2. Alerts appear grouped by **Risk**: High / Medium / Low / Informational.
3. Click any alert to see:
    - Which page(s) it was found on
    - A description of the issue
    - Suggested remediation

_You don't "start" a passive scan — it just runs automatically once traffic exists._

---

## 💥 3. Active Scanner (sends real attacks)

**What it does:** Takes every page/parameter from the Site Tree and throws test payloads at it (SQL injection, command injection, XSS, etc.) to confirm real vulnerabilities.

**How to run it from the ZAP UI:**

1. Go to the **Sites** tab.
2. Right-click the target URL → **Attack → Active Scan...**
    - If you haven't run the Spider yet, ZAP will run it first automatically to build the target list.
3. Configure options if needed (scan policy, which attack types to include), then click **Start Scan**.
4. Watch progress in the **Active Scan** tab (% complete, requests sent, current attack).
5. New alerts appear as they're confirmed — check the **Alerts** tab again once it's done.

> [!warning] Prioritize High risk alerts Sort/filter the **Alerts** tab by **High** risk first — these are the ones most likely to let you fully compromise the app or server (e.g. Remote OS Command Injection). Still review Medium/Low/Informational for a complete picture.

---

## 📄 4. Reporting

**How to generate a report from the ZAP UI:**

1. Top menu bar → **Report → Generate Report...**
2. Choose a format: **HTML**, **XML**, or **Markdown**.
3. Pick a save location and confirm.
4. Open the saved file in a browser (for HTML) to review the summary — total alert counts by risk level, plus details and fix suggestions for each.

> [!note] Reminder A generated report is raw scan data — useful as a log or appendix, but it should support your own write-up, not replace it, when reporting findings to a client or team.

---

## ✅ Quick recap (talking points)

- **Spider** = mapping the site (like Burp's Crawler). Run via `Sites tab → right-click → Attack → Spider`.
- **Ajax Spider** = mapping + catches JS-generated links. Run via `Attack → Ajax Spider`.
- **Passive Scan** = automatic, safe, background analysis — check the **Alerts** tab.
- **Active Scan** = sends real attack payloads to confirm vulnerabilities. Run via `Attack → Active Scan`.
- **Alerts tab** = where every finding lives, sorted by Risk + Confidence.
- **Report → Generate Report** = export findings as HTML/XML/Markdown.
